# 登录窗口与会话隔离

> 版本说明（2026-09-08）：当前正式版本为 **1.0.0**，支持范围见[1.0.0 发布范围](RELEASE-SCOPE-1.0.0.md)和[发布说明](RELEASE-NOTES-1.0.0.md)。本文技术说明和协议依据保留；带日期的测试、构建及登录尝试属于 0.1.0a1 阶段证据，不代替 1.0.0 的新产物验证，也不承诺全部设备或会话长期兼容。

当前生产源码为小米、OPPO、vivo、华为、荣耀、魅族和 WPS 使用独立的 WebView2 登录子进程。点击某个平台的“登录”时才启动对应进程；重复点击会调出已有窗口。每个新会话使用随机命名、互不共享的临时浏览器目录，并保持私密模式。应用不会复用 Edge 的个人资料目录，也不会在启动时自动打开七个平台。

每个官方窗口顶部提供“页面”菜单：“刷新当前页面”重新加载当前页，“重新打开官网”进入该平台预设的官方入口。两项由用户点击触发，保留当前窗口的会话，不清除其他平台状态，也不自动检查账号；重新进入笔记页后，仍须回到应用点击“已完成登录，检查账号”。菜单不接受外部 URL 参数。

用户在官方网页中完成密码、验证码和二次验证。官方窗口没有应用的 JS–Python 业务接口；检查登录时，会话仅经父子进程继承的内存 Pipe 交给 Python 后端。发送和接收两端都按该平台的官方域名范围筛选 Cookie，账号仍须通过实际笔记权限检查。密码、验证码、Cookie 和令牌不会交给应用主界面的 React 前端，也不会写入应用日志、命令行参数或会话存档。

检查成功后，官方窗口隐藏，供本次使用；导出页和迁移页共享后端已确认的账号状态。取消登录或退出应用会清除后端会话，并关闭相应登录进程。私密浏览器目录在正常关闭时由 WebView2 宿主清理。父进程退出、通信失败或超时也有受限的退出处理；强制终止或系统断电不能等同于已经验证过的正常目录清理。仅关闭官方窗口不等于在应用中“取消登录”。

本机合成测试曾复现 pywebview 6.2.1 在同一进程内新开私密窗口时清除另一窗口 Cookie 的情况。进程与目录隔离针对这一已复现问题；它不延长厂商会话有效期，也不能保证避免环境风险提示、验证码、网络故障或云端访问限制。出现这些提示时，以官方页面和软件的实际检查结果为准。
