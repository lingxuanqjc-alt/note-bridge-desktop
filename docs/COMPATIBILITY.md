七个已开放目标均检查图片原件类型、大小和 SHA256；扩展名或 MIME 不能使 GIF/WEBP 冒充 PNG/JPEG。各平台维持现有协议大小限制，未宣称完整分片实测通过。产品能力开关不依赖私有验收文件。普通任务成功表示厂商写入回执已确认，完整内容、图片、分组与手机同步是独立核对项目。

OPPO 官网的独立渲染核对确认了三处标记差异：斜体需使用 `<i>`，黄色高亮需使用 `highlight_color_yellow` 类，分隔线需使用带 `hr-style-solid` 类的 `<hr>`。生产适配器已修正这三处转换，并通过两项专项测试；高亮同时保留内联背景色以维持回读和本地导出的语义。官网下划线由渐变背景画线，检测已按精确可见线条与对应模型标记核对，无需修改原有下划线。OR1 及其余 11 条受影响样例已完成精确修复与官网核对，BI5[0] 无需修改并通过只读核对。修复会改变版本和更新时间，因此旧源端后置证据仅说明当时状态，原证明不覆盖或改写。

## 内容与转换

| 内容 | 支持范围及差异 |
| --- | --- |
| 中文、英文、Emoji、空标题、重名、长文本 | 统一模型、本地转换和部分真实来源已验证。重名以身份区分；空标题可能转为正文首行，原始字段和降级报告保留 |
| 标题、时间和常见富文本 | 目标无法设置原始时间时附注正文；加粗、斜体、下划线等按平台转换，不支持的高亮/删除线等列入报告；TXT 无法表达样式 |
| 列表、待办、引用、代码、表格 | 支持基础模型与四格式导出；云端无法表达的结构转可见文字并报告。嵌套、合并单元格和专有属性不能视为全面兼容 |
| 图片、音视频、其他文件 | 获取到的原件参与本地导出和相对资源打包；无法内嵌会提示。云端迁入仅 PNG/JPEG，不会静默删除不兼容附件 |
| 分组 | 保留来源组标识和名称，目标重名/过长会编号或调整并附注；映射按双方账号隔离。七平台均有归组接口样例证据；OPPO 本轮固定目标的官网分组已核对 |
| 专有手写、涂鸦、思维导图、加密内容 | 未支持的内容停止或明确报告，不能当作完整导出/迁移通过 |

OPPO 官网将代码块和行内代码呈现为普通文字，不能计作保留代码布局或等宽字体。生产报告会明确提示这一差异；代码文字与原始标记仍存于笔记内容中，供本地导出使用，不因官网显示降级而删除。

七平台已有四格式×两模式共 56 项基础缓存转换检查记录，历史快照合计 677 条。进一步独立渲染检查发现 Markdown 空白边界的强调损失，源码已修复并通过合成回归；两份旧 vivo Markdown 不改称完整样式通过。华为 BD2 不在该历史快照内。后续验收固定使用工具生成的测试笔记，vivo 不再全量读取私人笔记。数量和证据范围见 [发布前审查](RELEASE-READINESS.md)。

## 恢复与验收边界

同版本已确认写入会跳过；同一源笔记任一已关联旧版本仍在写入或结果不明时，新版本也会停止。迁移记录仅展示当前双方账号的本地回执和已关联历史记录，不自动确认云端内容，也不清除未知写入保护。历史 AD2、Z1、其他草稿和缺失基线记录保留，不重发。

本轮矩阵使用各来源平台直接建立的固定合成样例，不继续转发迁入样例，也不重做已通过条目。非 OPPO 的 30 个方向已由用户确认正常并冻结；OPPO 的 12 个方向分别有目标及源端后置证据。WPS、华为、荣耀共六条官网身份、正文、图片和目标保留样式通过；小米两条仅计已知视觉项目，vivo 由用户确认正常，魅族保留表格等预定降级。

华为 BI4 的两条目标由独立读取核对通过，原批次仍保留 `needs_review`；原有 22 条只核对存在及读取期间元数据稳定，没有重读全部正文。OPPO 历史固定目标官网核对已完成；完整内容/失败场景、全部界面状态、干净系统和手机同步仍有缺项。原广泛验收计划的迁移登记仍为 0/42，以 [acceptance.json](acceptance.json) 为准，不改成已通过。1.0.0 的限定发布范围与这些历史未完成项目分别说明，见 [1.0.0 发布范围](RELEASE-SCOPE-1.0.0.md)。
